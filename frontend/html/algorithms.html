Конструктор массива и редактор алгоритмов на C#

Выберите алгоритм в шапке, настройте входные данные и запустите код. Визуализация строится после выполнения программы по логам алгоритма.

Теория алгоритма

Сортировка вставками

Идея алгоритма

Сортировка вставками постепенно формирует отсортированную часть массива слева направо. Каждый новый элемент берется из неотсортированной части и вставляется на подходящее место среди уже отсортированных элементов.

Работа с массивом

Платформа передает в алгоритм TrackedList a.

Работайте с a как с обычным массивом:

  • обращайтесь к элементам по индексу, например a[i];
  • для получения количества элементов используйте a.Count.

Выводить что-либо в консоль не нужно. Платформа сама собирает шаги для визуализации и показывает результат.

Как работает алгоритм

Первый элемент считается уже отсортированным, поэтому обработка начинается со второго элемента.

На каждой итерации текущий элемент сохраняется в переменную key. Это нужно, чтобы не потерять его значение во время сдвигов.

Затем алгоритм двигается влево по отсортированной части массива. Пока проверяемый элемент больше key, он сдвигается на одну позицию вправо.

Когда найден элемент, который не больше key, или достигнута левая граница массива, key вставляется на освободившееся место.

После этого отсортированная часть массива становится длиннее на один элемент.

Важно помнить

Сортировка вставками выполняет именно сдвиги элементов вправо, а не обмены соседних элементов. Если вместо сдвигов делать обмены, визуализация будет показывать другой алгоритм.

Сортировка выбором

Идея алгоритма

Сортировка выбором постепенно формирует отсортированную часть массива слева направо. На каждой итерации алгоритм ищет минимальный элемент в неотсортированной части и помещает его на текущую позицию.

Работа с массивом

Платформа передает в алгоритм TrackedList a.

Работайте с a как с обычным массивом:

  • обращайтесь к элементам по индексу, например a[i];
  • для получения количества элементов используйте a.Count;
  • для обмена значений используйте a.Swap(i, j).

Выводить что-либо в консоль не нужно. Платформа сама собирает шаги для визуализации и показывает результат.

Как работает алгоритм

Обход начинается с элемента с индексом 0 и продолжается до предпоследнего элемента. Последний элемент отдельно обрабатывать не нужно, потому что к этому моменту он уже окажется на правильной позиции.

На каждой итерации текущая позиция считается местом, куда нужно поставить минимальный элемент из оставшейся части массива.

Сначала индекс текущей позиции запоминается как индекс минимального элемента. Затем внутренний проход просматривает все элементы справа от текущей позиции.

Если во внутреннем проходе находится элемент меньше текущего минимума, индекс минимума обновляется.

После завершения внутреннего прохода найденный минимум помещается на текущую позицию. Если минимум уже находится на текущей позиции, обмен делать не нужно. Если минимум находится в другом месте, элементы меняются местами с помощью a.Swap(i, j).

Важно помнить

Внутренний цикл должен только искать индекс минимального элемента. Менять элементы местами внутри внутреннего цикла не нужно.

Для каждой внешней итерации выполняется не больше одного обмена. Если делать обмены сразу при нахождении меньшего элемента, появятся лишние шаги визуализации, и алгоритм будет выглядеть не как сортировка выбором.

Быстрая сортировка со схемой Хоара

Идея алгоритма

Быстрая сортировка делит массив на две части относительно опорного элемента. После разбиения элементы слева должны быть меньше или равны элементам справа. Затем каждая часть сортируется рекурсивно тем же способом.

В этой реализации используется классическая схема разбиения Хоара.

Работа с массивом

Платформа передает в алгоритм TrackedList a.

Работайте с a как с обычным массивом:

  • обращайтесь к элементам по индексу, например a[i];
  • для получения количества элементов используйте a.Count;
  • для обмена значений используйте a.Swap(i, j).

Выводить что-либо в консоль не нужно. Платформа сама собирает шаги для визуализации и показывает результат.

Структура алгоритма

Алгоритм удобно разделить на две функции:

  • QuickSort - рекурсивно сортирует текущий диапазон массива;
  • PartitionHoare - выполняет разбиение диапазона и возвращает индекс разделения split.

Как работает QuickSort

Функция получает границы текущего диапазона: left и right.

Сначала проверяется базовый случай. Если left >= right, в диапазоне находится ноль или один элемент, поэтому сортировать его не нужно.

Если left < right, вызывается разбиение Хоара. После разбиения функция получает индекс split и рекурсивно сортирует две части массива:

  • от left до split;
  • от split + 1 до right.

Как работает PartitionHoare

В качестве опорного элемента выбирается элемент из середины текущего диапазона.

Затем создаются два указателя:

  • левый указатель ставится перед началом диапазона;
  • правый указатель ставится после конца диапазона.

Дальше указатели двигаются навстречу друг другу:

  • левый указатель идет вправо, пока встречает элементы меньше опорного;
  • правый указатель идет влево, пока встречает элементы больше опорного.

Когда оба указателя остановились, проверяется их положение.

Если левый указатель стал больше или равен правому, разбиение завершено. Функция возвращает правый указатель как split.

Если указатели еще не пересеклись, элементы на их позициях меняются местами с помощью a.Swap(i, j). После этого разбиение продолжается.

Важно помнить

В схеме Хоара split - это граница разбиения, а не обязательно окончательная позиция опорного элемента. Поэтому после разбиения нужно сортировать диапазоны left..split и split + 1..right.

Не нужно отдельно ставить опорный элемент на финальную позицию. В схеме Хоара этого шага нет.

Типичные ошибки

Частые ошибки при реализации:

  • указать неправильное условие базового случая;
  • вернуть не тот указатель из функции разбиения;
  • использовать неверные границы рекурсивных вызовов;
  • пытаться отдельно поставить опорный элемент на место;

Из-за таких ошибок возможны бесконечная рекурсия, пропуск части массива, неправильная сортировка или некорректная визуализация шагов.

Бинарный поиск

Идея алгоритма

Бинарный поиск ищет значение в отсортированном массиве. На каждом шаге алгоритм рассматривает текущий диапазон поиска, выбирает его середину и сравнивает средний элемент с искомым значением.

Если средний элемент не равен искомому, одна из половин диапазона отбрасывается. Поэтому с каждым шагом область поиска уменьшается примерно в два раза.

Работа с массивом

Платформа передает в алгоритм TrackedList a и искомое значение target.

Работайте с a как с обычным массивом:

  • обращайтесь к элементам по индексу, например a[i];
  • для получения количества элементов используйте a.Count.

Выводить что-либо в консоль не нужно. Платформа сама собирает шаги для визуализации и показывает результат.

Как работает алгоритм

Сначала задаются границы текущего диапазона поиска:

  • левая граница указывает на начало массива;
  • правая граница указывает на конец массива.

Пока левая граница не стала больше правой, диапазон поиска не пустой.

На каждой итерации выбирается средний индекс текущего диапазона. Затем элемент в середине сравнивается с target.

Если средний элемент равен target, поиск завершен, и алгоритм возвращает индекс найденного элемента.

Если средний элемент меньше target, значит искомое значение может находиться только справа от середины. В этом случае левая граница переносится на элемент после середины.

Если средний элемент больше target, значит искомое значение может находиться только слева от середины. В этом случае правая граница переносится на элемент перед серединой.

Если границы пересеклись, значит диапазон поиска стал пустым, а элемент не найден. В этом случае алгоритм возвращает -1.

Важно помнить

Бинарный поиск работает корректно только на отсортированном массиве.

Условие продолжения поиска должно учитывать случай, когда в диапазоне остался один элемент. Поэтому диапазон считается непустым, пока левая граница меньше или равна правой.

Типичные ошибки

Частые ошибки при реализации:

  • запускать бинарный поиск на неотсортированном массиве;
  • неверно обновлять левую или правую границу;
  • использовать условие цикла, которое пропускает последний оставшийся элемент;
  • не обработать ситуацию, когда значение не найдено;
  • после проверки середины не исключать ее из следующего диапазона.

Из-за таких ошибок алгоритм может вернуть неверный индекс, уйти в бесконечный цикл или не найти существующий элемент.

Поиск в ширину

Идея алгоритма

Поиск в ширину, или BFS, обходит граф слоями. Сначала проверяются вершины, находящиеся на расстоянии одного перехода от старта, затем вершины на расстоянии двух переходов и так далее.

В невзвешенном графе BFS позволяет найти кратчайший маршрут по количеству ребер. Если маршрут найден, он записывается в out List<int> path.

Работа с графом

Платформа передает в алгоритм TrackedAdjacencyList adj, начальную вершину start и конечную вершину end.

Работайте с adj как со списком смежности:

  • adj.Count возвращает количество вершин в графе;
  • adj[v] возвращает соседей вершины v;
  • для хранения посещенных вершин используйте TrackedVisited;
  • для обхода используйте TrackedQueue;
  • найденный маршрут нужно записать в path.

Выводить что-либо в консоль не нужно. Платформа сама собирает шаги для визуализации и показывает результат.

Как работает алгоритм

Сначала создается пустой список path, в который позже будет записан найденный маршрут.

Затем нужно получить количество вершин графа через adj.Count и проверить, что start и end находятся в допустимых границах. Если хотя бы один индекс некорректный, функция сразу возвращает false, а путь остается пустым.

Если начальная и конечная вершины совпадают, маршрут уже найден. В этом случае достаточно добавить start в path и вернуть true.

После этого подготавливаются структуры для обхода:

  • visited хранит информацию о посещенных вершинах;
  • parent хранит, из какой вершины впервые пришли в каждую вершину;
  • q хранит очередь вершин, которые нужно обработать.

Перед началом обхода стартовая вершина отмечается как посещенная и добавляется в очередь.

Пока очередь не пустая, из нее извлекается очередная вершина. Если эта вершина равна end, поиск можно остановить: кратчайший маршрут до конечной вершины уже найден.

Если текущая вершина не является конечной, алгоритм просматривает всех ее соседей. Каждый непосещенный сосед отмечается как посещенный, для него сохраняется родительская вершина, после чего сосед добавляется в очередь.

После завершения обхода нужно проверить, была ли посещена конечная вершина. Если end не был посещен, маршрута между start и end нет, поэтому функция возвращает false.

Если конечная вершина была посещена, маршрут восстанавливается через массив родителей. Для этого нужно идти от end назад к start, каждый раз переходя к родителю текущей вершины. Такой путь строится в обратном порядке, поэтому после восстановления его нужно развернуть.

После этого итоговый маршрут находится в path, а функция возвращает true.

Важно помнить

BFS использует очередь, поэтому вершины обрабатываются в порядке их удаления от стартовой вершины. Именно поэтому для невзвешенного графа найденный путь будет кратчайшим по количеству ребер.

Вершину нужно отмечать посещенной в момент добавления в очередь. Так одна и та же вершина не будет добавлена в очередь несколько раз.

Для восстановления маршрута используется массив parent. В нем для каждой вершины хранится вершина, из которой в нее впервые пришли.

Типичные ошибки

Частые ошибки при реализации:

  • проверять start и end уже после обращения к графу;
  • не обработать случай, когда start == end;
  • отмечать вершину посещенной только при извлечении из очереди;
  • не сохранять родителя для найденной вершины;
  • не учитывать направление ребер в графе;
  • забыть проверить, была ли достигнута конечная вершина;
  • восстановить путь от end к start, но не развернуть его;
  • очистить path после успешного восстановления маршрута.

Из-за таких ошибок алгоритм может выйти за границы графа, добавить одну вершину в очередь несколько раз, не восстановить кратчайший путь или вернуть маршрут в неправильном порядке.

Поиск в глубину

Идея алгоритма

Поиск в глубину, или DFS, обходит граф, стараясь пройти как можно дальше по одному направлению. Если выбранная ветка не приводит к нужной вершине, алгоритм возвращается назад и продолжает проверять другие варианты.

В этой задаче DFS используется для проверки, существует ли маршрут от начальной вершины до конечной. Если маршрут найден, он записывается в out List<int> path.

Работа с графом

Платформа передает в алгоритм TrackedAdjacencyList adj, начальную вершину start и конечную вершину end.

Работайте с adj как со списком смежности:

  • adj.Count возвращает количество вершин в графе;
  • adj[v] возвращает соседей вершины v;
  • для хранения посещенных вершин используйте TrackedVisited;
  • для обхода используйте TrackedStack;
  • найденный маршрут нужно записать в path.

Выводить что-либо в консоль не нужно. Платформа сама собирает шаги для визуализации и показывает результат.

  • stack хранит вершины, которые еще нужно обработать.

После этого итоговый маршрут находится в path, а функция возвращает true.

Важно помнить

В этой реализации DFS выполняется не рекурсией, а с помощью стека. Это позволяет явно управлять порядком обхода и удобно собирать шаги для визуализации.

Вершину нужно отмечать посещенной в момент добавления в стек. Так одна и та же вершина не будет добавлена в стек несколько раз.

Типичные ошибки

Частые ошибки при реализации:

  • проверять start и end уже после обращения к графу;
  • не обработать случай, когда start == end;
  • не отмечать вершины как посещенные;
  • отмечать вершину посещенной слишком поздно;
  • не сохранять родителя для найденной вершины;
  • забыть проверить, была ли достигнута конечная вершина;
  • восстановить путь от end к start, но не развернуть его;
  • вернуть true, не записав найденный маршрут в path.

Из-за таких ошибок алгоритм может выйти за границы графа, зациклиться, не найти существующий путь или вернуть маршрут в неправильном порядке.

Песочница алгоритма

Выберите шаблон ниже и смотрите справку по функциям логирования для массива или графа.

Шаблон для массива

Этот шаблон нужен для сортировок и бинарного поиска. В нём используется обычный int[] a, а не TrackedList. Ниже показано, как вызывать функции логирования прямо в коде.

  • TracingExtensions.EmitArray(t, a.ToArray()) отправляет текущий массив на сцену до запуска алгоритма.
  • Read(a[i]) или t.Read(i) отмечает чтение элемента.
  • Compare(a[i], a[j]) или t.Compare(i, j) отмечает сравнение двух элементов.
  • Swap(a[i], a[j]) или t.Swap(i, j) отмечает обмен двух элементов.
  • TracingExtensions.MarkKey(t, i), TracingExtensions.MarkMin(t, i), TracingExtensions.MarkPivot(t, i) и TracingExtensions.MarkSorted(t, i) дают готовые смысловые метки.
  • Range(t, "window", l, r) или TracingExtensions.Range(t, "window", l, r, "active") показывает активный диапазон, а TracingExtensions.ClearRange(t, "window") и TracingExtensions.ClearRanges(t) убирают подсветку.
  • Ptr(t, "i", index) или TracingExtensions.Ptr(t, "i", index, "left") показывает указатель алгоритма.
  • t.Step("Текст шага") можно использовать для дополнительного текстового шага.
Фронтенд анимирует кружки массива, их чтение, сравнение, обмен, подсветку ключа, минимума, pivot, отсортированной части, диапазоны и указатели. Запись значения анимируется через обычное присваивание в массиве.

Шаблон для графа

Этот шаблон нужен для BFS и DFS. Ниже показано, как вызывать функции логирования прямо в коде.

  • var visited = new TrackedVisited(V, adj) отслеживает посещённые вершины.
  • var q = new TrackedQueue(adj) хранит очередь BFS.
  • var stack = new TrackedStack(adj) хранит стек DFS.
  • adj.GraphInit(startLabel, endLabel) задаёт старт и финиш для сцены графа.
  • adj.Path(path) подсвечивает найденный путь.
  • adj.NotFound() показывает, что маршрут не найден.
Фронтенд анимирует вершины, рёбра, старт, финиш, очередь или стек, посещённые вершины и итоговый путь. Для BFS и DFS маршрут собирается в out List<int> path.
