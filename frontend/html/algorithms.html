Конструктор массива и редактор алгоритмов на C#

Выберите алгоритм в шапке, настройте входные данные и запустите код. Визуализация строится после выполнения программы по логам алгоритма.

Теория алгоритма

Сортировка вставками

Что нужно написать: только алгоритм сортировки. Платформа сама передает массив, собирает шаги для визуализации и показывает результат. Выводить что-либо в консоль не нужно.

Идея: слева постепенно формируется отсортированная часть массива. Каждый следующий элемент временно считается ключом, большие элементы из отсортированной части сдвигаются вправо, после чего ключ вставляется на освободившееся место.

Шаги написания алгоритма:

  1. Начните со второго элемента, потому что первый элемент сам по себе уже образует отсортированную часть.
  2. Сохраните текущий элемент как ключ, иначе при первом сдвиге его значение будет потеряно.
  3. Двигайтесь влево по отсортированной части и сравнивайте элементы с ключом.
  4. Пока элемент слева больше ключа, сдвигайте этот элемент на одну позицию вправо.
  5. Когда найдено начало массива или элемент, который не больше ключа, вставьте ключ сразу после него.
  6. После каждой внешней итерации отсортированная часть становится на один элемент длиннее.

Типичные ошибки: забыть сохранить ключ перед сдвигами, вставить ключ не в ту позицию, выйти за левую границу массива, случайно сделать обмены вместо сдвигов и получить визуально другой алгоритм.

К чему это приводит: элемент может потеряться, массив останется частично неотсортированным, анимация будет показывать обмены вместо настоящей вставки.

Сортировка выбором

Что нужно написать: только алгоритм сортировки. Платформа сама передает массив, собирает шаги для визуализации и показывает результат. Выводить что-либо в консоль не нужно.

Идея: массив делится на отсортированную левую часть и неотсортированную правую часть. Для первой позиции неотсортированной части ищется минимальный элемент справа, после чего он один раз меняется местами с текущей позицией.

Шаги написания алгоритма:

  1. Проходите по позициям массива слева направо.
  2. Для каждой позиции считайте ее текущим местом, куда нужно поставить минимальный элемент из оставшейся части.
  3. Запоминайте позицию минимального элемента, а не само значение: потом именно эту позицию нужно использовать для обмена.
  4. Во внутреннем проходе сравните все элементы справа с текущим минимумом.
  5. Если найден меньший элемент, обновите позицию минимума.
  6. После завершения внутреннего прохода сделайте не больше одного обмена: текущая позиция и найденный минимум.

Типичные ошибки: менять элементы местами внутри внутреннего цикла, не сбрасывать минимум на новой итерации, сравнивать новый элемент не с текущим минимумом, а с начальной позицией.

К чему это приводит: появляется лишняя анимация обменов, алгоритм становится похож на другую сортировку, часть массива может остаться неотсортированной.

Быстрая сортировка

Что нужно написать: только алгоритм сортировки. Платформа сама передает массив, собирает шаги для визуализации и показывает результат. Выводить что-либо в консоль не нужно.

Идея: выбирается опорный элемент. Текущий диапазон массива перестраивается так, чтобы слева оказались элементы меньше опорного, а справа элементы больше опорного. Затем тот же принцип применяется рекурсивно к левой и правой частям.

Шаги написания алгоритма:

  1. Перед началом обработки диапазона проверьте базовый случай: если в диапазоне ноль или один элемент, его уже не нужно сортировать.
  2. Выберите опорный элемент. В учебной реализации удобно брать середину диапазона, чтобы визуально было понятно, от чего идет разделение.
  3. Поставьте левый и правый указатели на границы текущего диапазона.
  4. Двигайте левый указатель вправо, пока он стоит на элементах меньше опорного.
  5. Двигайте правый указатель влево, пока он стоит на элементах больше опорного.
  6. Когда оба указателя остановились, элементы на них находятся не в своих частях. Если указатели еще не пересеклись, обменяйте эти элементы.
  7. После обмена сдвиньте оба указателя дальше, чтобы не зациклиться на тех же позициях.
  8. Когда разделение завершено, рекурсивно отсортируйте левую и правую части, которые получились после пересечения указателей.

Типичные ошибки: забыть базовый случай, не сдвинуть указатели после обмена, неправильно выбрать границы рекурсивных вызовов, некорректно обработать элементы, равные опорному.

К чему это приводит: рекурсия может стать бесконечной, часть массива не попадет в сортировку, одинаковые значения могут ломать разделение.

Бинарный поиск

Что нужно написать: только алгоритм поиска. Платформа сама передает отсортированный массив и искомое значение, собирает шаги для визуализации и показывает результат. Выводить что-либо в консоль не нужно.

Идея: поиск работает только на отсортированном массиве. На каждом шаге рассматривается текущий диапазон, выбирается середина и по сравнению с искомым значением отбрасывается левая или правая половина.

Шаги написания алгоритма:

  1. Задайте левую и правую границы диапазона поиска: начало и конец массива.
  2. Пока диапазон не пустой, выбирайте середину между границами.
  3. Сравните средний элемент с искомым значением.
  4. Если значения равны, верните позицию найденного элемента.
  5. Если средний элемент меньше искомого, продолжайте поиск только справа от середины.
  6. Если средний элемент больше искомого, продолжайте поиск только слева от середины.
  7. Если диапазон стал пустым, верните отрицательный результат поиска.

Типичные ошибки: запускать поиск на неотсортированном массиве, неверно обновлять границы, использовать условие цикла, которое пропускает один элемент, не обработать ситуацию “не найдено”.

К чему это приводит: алгоритм может вернуть неверную позицию, уйти в бесконечный цикл или не найти существующий элемент.

Поиск в ширину (BFS)

Что нужно написать: только алгоритм поиска кратчайшего маршрута в графе. Платформа сама передает граф, начальную и конечную вершины, собирает шаги для визуализации и показывает результат. Выводить что-либо в консоль не нужно.

Идея: BFS обходит граф слоями. Сначала проверяются вершины на расстоянии один переход от старта, потом на расстоянии два перехода и так далее. Поэтому для невзвешенного графа BFS находит кратчайший путь по количеству ребер.

Шаги написания алгоритма:

  1. Подготовьте очередь вершин, массив посещенных вершин и массив родителей.
  2. Сначала проверьте, что начальная и конечная вершины находятся в границах графа. Если хотя бы одна граница неверная, путь должен быть пустым, а результат поиска отрицательным.
  3. Если стартовая и конечная вершины совпадают, добавьте стартовую вершину в out List<int> path и завершите поиск успешно.
  4. Поместите начальную вершину в очередь, отметьте ее посещенной, а ее родителя обозначьте как отсутствующего.
  5. Пока очередь не пуста, доставайте вершину из начала очереди.
  6. Если достали конечную вершину, маршрут найден и обход можно завершить.
  7. Для каждого соседа текущей вершины проверьте, был ли он посещен.
  8. Если сосед еще не посещен, отметьте его, запишите текущую вершину как его родителя и добавьте соседа в очередь.
  9. Если конечная вершина не была достигнута, итоговый путь должен быть пустым, а алгоритм должен вернуть отрицательный результат.
  10. Если путь найден, восстановите его с конца: начните с конечной вершины, затем переходите к ее родителю, потом к родителю родителя и так до начальной вершины.
  11. Полученный обратный порядок разверните. Итоговый маршрут записывается в out List<int> path, а функция возвращает признак успешного поиска.

Типичные ошибки: проверять start и end после обращения к массивам, отмечать вершину посещенной только при извлечении из очереди, не сохранять родителя, не учитывать направление ребер, очищать путь после успешного поиска.

К чему это приводит: неверный индекс вызывает исключение, одна вершина может попадать в очередь несколько раз, кратчайший путь невозможно восстановить, найденный маршрут может идти по несуществующим ребрам.

Поиск в глубину (DFS)

Что нужно написать: только алгоритм проверки существования маршрута в графе. Платформа сама передает граф, начальную и конечную вершины, собирает шаги для визуализации и показывает результат. Выводить что-либо в консоль не нужно.

Идея: DFS пытается пройти как можно глубже по одному направлению, а если путь не приводит к цели, возвращается назад и пробует следующий вариант. Такой обход хорошо подходит для проверки, существует ли маршрут между двумя вершинами.

Шаги написания алгоритма:

  1. Подготовьте структуру для посещенных вершин, чтобы не ходить по циклам бесконечно.
  2. Сначала проверьте, что начальная и конечная вершины находятся в границах графа. Если индекс неверный, путь должен быть пустым, а функция должна вернуть отрицательный результат.
  3. Если стартовая и конечная вершины совпадают, добавьте стартовую вершину в out List<int> path и завершите поиск успешно.
  4. Начните обход из стартовой вершины и сразу отметьте ее посещенной.
  5. Если текущая вершина равна конечной, маршрут найден.
  6. Иначе по очереди переходите к соседям, которые еще не были посещены.
  7. Если рекурсивный вызов или стековый переход нашел конечную вершину, сразу возвращайте успешный результат вверх по цепочке вызовов.
  8. Если все соседи проверены и цель не найдена, вернитесь назад и продолжите проверку других веток.
  9. Если нужно вернуть сам маршрут, добавляйте вершины только в успешную ветку либо сохраняйте родителей так же, как в BFS.
  10. Итоговый маршрут записывается в out List<int> path, а функция возвращает признак успешного поиска. При восстановлении через родителей путь строится от конечной вершины назад к стартовой, а затем разворачивается.

Типичные ошибки: проверять start и end после обращения к массивам, не отмечать посещенные вершины, возвращать неудачу после первого неподходящего соседа, не передавать успешный результат вверх, забыть удалить вершину из временного пути при откате.

К чему это приводит: неверный индекс вызывает исключение, обход может зациклиться, алгоритм может сказать, что пути нет, хотя он есть, или показать путь, который относится к другой ветке поиска.

Общее правило: пользователь пишет алгоритм внутри подготовленной функции. Чтение входных данных, запуск функции и отправка событий визуализации уже находятся в шаблоне.

Если алгоритм связан с графом и должен вернуть маршрут, итоговый путь записывается в out List<int> path.

Песочница алгоритма

Выберите шаблон ниже и смотрите справку по функциям логирования для массива или графа.

Шаблон для массива

Этот шаблон нужен для сортировок и бинарного поиска. В нём используется обычный int[] a, а не TrackedList. Ниже показано, как вызывать функции логирования прямо в коде.

  • TracingExtensions.EmitArray(t, a.ToArray()) отправляет текущий массив на сцену до запуска алгоритма.
  • Read(a[i]) или t.Read(i) отмечает чтение элемента.
  • Compare(a[i], a[j]) или t.Compare(i, j) отмечает сравнение двух элементов.
  • Swap(a[i], a[j]) или t.Swap(i, j) отмечает обмен двух элементов.
  • TracingExtensions.MarkKey(t, i), TracingExtensions.MarkMin(t, i), TracingExtensions.MarkPivot(t, i) и TracingExtensions.MarkSorted(t, i) дают готовые смысловые метки.
  • Range(t, "window", l, r) или TracingExtensions.Range(t, "window", l, r, "active") показывает активный диапазон, а TracingExtensions.ClearRange(t, "window") и TracingExtensions.ClearRanges(t) убирают подсветку.
  • Ptr(t, "i", index) или TracingExtensions.Ptr(t, "i", index, "left") показывает указатель алгоритма.
  • t.Step("Текст шага") можно использовать для дополнительного текстового шага.
Фронтенд анимирует кружки массива, их чтение, сравнение, обмен, подсветку ключа, минимума, pivot, отсортированной части, диапазоны и указатели. Запись значения анимируется через обычное присваивание в массиве.

Шаблон для графа

Этот шаблон нужен для BFS и DFS. Ниже показано, как вызывать функции логирования прямо в коде.

  • var visited = new TrackedVisited(V, adj) отслеживает посещённые вершины.
  • var q = new TrackedQueue(adj) хранит очередь BFS.
  • var stack = new TrackedStack(adj) хранит стек DFS.
  • adj.GraphInit(startLabel, endLabel) задаёт старт и финиш для сцены графа.
  • adj.Path(path) подсвечивает найденный путь.
  • adj.NotFound() показывает, что маршрут не найден.
Фронтенд анимирует вершины, рёбра, старт, финиш, очередь или стек, посещённые вершины и итоговый путь. Для BFS и DFS маршрут собирается в out List<int> path.
