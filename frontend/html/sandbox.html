Песочница алгоритма

Эта страница описывает, как устроены шаблоны кода, какие структуры нужны для визуализации и какие функции логирования доступны в алгоритмах.

Главное правило

В редакторе алгоритма уже подготовлен полный файл: чтение входных данных, создание структур, запуск функции алгоритма и отправка событий визуализации.

Пользователь меняет только функцию алгоритма. Выводить результат в консоль не нужно: фронтенд строит визуализацию по логам, которые собирает библиотека.

Шаблон для массивов

Для сортировок и бинарного поиска используется функция алгоритма, которая получает отслеживаемый массив и объект логирования.

static void AlgorithmName(TrackedList a, ITracer t)
{
  // Здесь пользователь пишет алгоритм.
}

TrackedList a ведет себя как массив, но дополнительно логирует чтения, сравнения, записи и обмены. Если заменить его на обычный массив, автоматическая визуализация потеряет часть событий.

ITracer t нужен для ручного логирования: через него можно явно отметить ключ, минимум, опорный элемент, диапазон, указатель или дополнительный шаг.

Шаблон для графов

Для DFS и BFS используется единый подход: функция возвращает признак найденного маршрута, а сам маршрут записывает в выходной параметр.

static bool AlgorithmName(
  TrackedAdjacencyList adj,
  int start,
  int end,
  out List<int> path)
{
  // Здесь пользователь пишет алгоритм.
}

TrackedAdjacencyList adj хранит список смежности и логирует проверку ребер при переборе соседей.

start и end — номера начальной и конечной вершины. Их нужно проверять до обращения к массивам посещений или родителей.

out List<int> path содержит итоговый маршрут. Обычно путь восстанавливается от конечной вершины к начальной через массив родителей, затем разворачивается.

Структуры графа

TrackedVisited показывает, какие вершины уже посещены. Без него визуализация не узнает, когда вершина стала обработанной.

TrackedQueue используется в BFS и показывает вершины, ожидающие обработки в очереди.

TrackedStack используется в DFS и показывает вершины, ожидающие обработки в стеке.

adj.Path(path) подсвечивает найденный маршрут, а adj.NotFound() показывает, что пути нет.

Функции логирования массивов

EmitArray отправляет текущее состояние массива на сцену. Обычно это делает подготовленный Main перед запуском алгоритма.

Read показывает чтение элемента.

Compare показывает сравнение двух элементов.

Write показывает запись значения в позицию массива.

Swap показывает обмен двух элементов.

MarkKey, MarkMin, MarkPivot и MarkSorted выделяют смысловые элементы алгоритма.

Range показывает активный диапазон, а Ptr показывает указатель алгоритма.

Когда анимация не будет работать корректно

  • Если пользователь выводит произвольный текст в консоль вместо работы со структурами.
  • Если в алгоритме используются обычные коллекции вместо TrackedList или TrackedAdjacencyList.
  • Если для графа не заполняется out List<int> path при найденном маршруте.
  • Если start и end проверяются после обращения к массивам.
  • Если события ручного логирования не соответствуют реальным действиям алгоритма.
